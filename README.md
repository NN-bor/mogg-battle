# mog battle

Аттракцион на перемену для интерактивной панели. Двое встают рядом перед камерой. Приложение находит оба лица, рисует по ним технические линии и показывает каждому одно число: итог по десятибалльной шкале. Проигравшему глаза перечёркивает толстая красная полоса с надписью MOGGED.

Линии строятся по настоящим лэндмаркам, а цифры нарочно выдуманы. Это театр, а не оценка внешности.

Ванильный JS (ES modules), без фреймворков и сборки. Работает офлайн, на устройстве ничего не записывается.

---

## Быстрый старт

**Windows:** двойной клик по `start.bat`. Нужен [Node.js 18+](https://nodejs.org). Скрипт при первом запуске скачает ассеты (~25 МБ), поднимет сервер и откроет Edge на `http://localhost:8080`.

**Любая ОС:**

```bash
npm start            # = node scripts/serve.mjs --open
```

Скачать ассеты отдельно: `node scripts/fetch-assets.mjs` (добавьте `--force` для перекачки). Если сеть идёт через прокси, задайте `NODE_USE_ENV_PROXY=1`, а для своего корневого сертификата `NODE_EXTRA_CA_CERTS=путь.pem`.

> Камера в браузере работает только по `https://` или `http://localhost`. Двойной клик по `index.html` (`file://`) не подойдёт: приложение покажет экран с объяснением.

## Выкладка

### GitHub Pages (рекомендую: репозиторий уже на GitHub)

1. Settings → Pages → Source: **GitHub Actions**.
2. Слейте ветку в `main`. Workflow `.github/workflows/pages.yml` сам скачает ассеты и опубликует сайт на `https://<user>.github.io/mogg-battle/`.

Все пути в приложении относительные, поэтому оно работает и из подпапки.

### Cloudflare Pages

Dashboard → Workers & Pages → Create → Pages → Connect to Git, затем:

- Framework preset: **None**
- Build command: `node scripts/fetch-assets.mjs`
- Build output directory: `/`
- Переменная окружения `NODE_VERSION = 22`

Файл `_headers` уже лежит в корне. Самый крупный файл весит 10.6 МБ, это укладывается в лимит Cloudflare в 25 МБ.

### Установка на панель как приложения (PWA в Edge)

1. Откройте опубликованный адрес в Edge на панели и один раз разрешите камеру.
2. Значок «Приложение доступно» в адресной строке (или меню ⋯ → Приложения → Установить этот сайт как приложение).
3. Запускайте из «Пуска». Окно откроется на весь экран (`display: fullscreen`). Service worker кэширует wasm, модель и шрифты, после первого запуска сеть не нужна.
4. Для автозапуска положите ярлык приложения в `shell:startup`. Режим киоска настраивается через Параметры Windows → Учётные записи → Другие пользователи → Киоск (Edge, полноэкранный режим, ваш URL).

Wake Lock держит экран включённым, пока приложение на экране, но электропитание Windows стоит всё равно проверить.

## Управление

- Только касания. Hover, правый клик, щипок, выделение и курсор выключены.
- **Старт** появляется, когда оба лица держатся в кадре 1 с. Первый тап включает звук, fullscreen и Wake Lock.
- **Реванш** сохраняет счёт серии, **Новые игроки** его сбрасывают. Если в кадре никого нет 10 с, серия сбрасывается сама: значит, пришла новая пара.
- **Скрытые настройки:** удерживайте пустой левый верхний угол экрана 1.5 с. Там камера, зеркало, зум кадра, шум очков, звук, вход детектора, оверлей FPS. Настройки хранятся в `localStorage`, больше приложение ничего не сохраняет.
- Клавиатура (если подключена): `Enter`/`Пробел` нажимает Старт или Реванш, `,` открывает настройки, `Esc` их закрывает.
- Диагностика в адресе: `?debug` выводит внутренности в консоль (`window.mog`), `?cpu` принудительно включает CPU-делегат, `?nosw` отключает service worker.

## Что решено по умолчанию

ТЗ разрешало задать до 5 вопросов. Отвечать было некому, поэтому везде взят вариант по умолчанию:

1. **Разрешение и масштаб Windows неизвестны.** Интерфейс построен на `vh` и не зависит от разрешения, canvas-оверлей рендерится не выше 1920×1080 и растягивается CSS.
2. **Камера неизвестна** (встроенная или USB, угол обзора, высота). Детектор ищет лица по всему кадру на трёх масштабах, отображение кадрирует игроков само. Камеру можно выбрать в настройках.
3. **Хостинг.** GitHub Pages через Actions, плюс инструкция для Cloudflare Pages и локальный `start.bat`.
4. **Язык.** Интерфейс на русском. Названия метрик (JAWLINE, CANTHAL TILT…) живут только в коде и в `?debug`.
5. **Звук** включён по умолчанию и тихий. Выключается в настройках.

## Где я отступил от ТЗ и почему

**1. Детектор работает не на одном кадре 640×360, а на мозаике из двух тайлов.** Встроенный в Face Landmarker детектор (BlazeFace short-range, вход 128×128) не видит лица меньше ~12–15% ширины входа. Я это измерил: на тестовом кадре, где лица занимают 5% ширины (широкоугольная камера на 1.5 м), лица не нашлись ни при каком зуме до 2×.

Поэтому у каждого игрока свой квадратный кроп полного кадра камеры. Он следит за лицом, оба кропа идут бок о бок в один вход ~666×320. По нагрузке это столько же, сколько один кадр 640×360, но лицо занимает ~40% тайла, а лэндмарки считаются по пикселям полного разрешения. Пока лицо не найдено, тайл перебирает сетку кропов на трёх масштабах по своей половине кадра. После этого изменения то же тестовое видео стабильно ловится примерно за секунду.

Попутно пропала проблема левого и правого игрока: идентичность задаёт тайл, а порядок перепроверяется с гистерезисом (`assign.js`). `numFaces = 3`: третий слот запасной, чтобы чужое лицо на краю тайла не вытесняло игрока. В каждом тайле берётся лицо, ближайшее к центру.

**2. Автокадрирование кадра (зум «Авто»).** Детектор больше не зависит от отображения, поэтому экран сам приближает игроков, как оператор: лица крупные, внизу по углам остаётся место под карточки счёта. Если в кадре один игрок, он встаёт на свою половину, а пустой овал зовёт второго. Во время раунда кадр почти не двигается. В настройках можно выбрать фиксированный зум 1×–2×.

**3. Дизайн v1.1 (по фидбеку после первой версии).**
- Человек видит одно число: итог 3.00–10.00 на карточке в своём нижнем углу. Шесть метрик, их единицы и подписи углов на линиях убраны с экрана и работают внутри.
- Во время скана число «бежит» вживую: поднял брови, и итог растёт. Раскрытие идёт в таком порядке: сначала фиксируется меньший итог, через 0.7 с больший, затем удар.
- Проигравшему глаза перечёркивает толстая красная полоса (`--mog: #FF3B30`) с белой надписью MOGGED. Полоса наклонена на 5°, следит за лицом и не заходит на половину соперника. Чёрных плашек нет. Это второй цвет вопреки правилу «один акцент» из ТЗ, по прямой просьбе.
- Победитель: число, полоска и обводка карточки в акцентном цвете, тег «ПОБЕДА». Отдельной рамки вокруг половины больше нет, половина проигравшего затемнена.
- Убраны wordmark «mog battle» и строка «Цифры выдуманные…». Настройки открываются удержанием пустого левого верхнего угла.
- Шрифт тяжёлый и игровой: Inter 800 для чисел и отсчёта, 700 для подсказок, кнопок и подписей.
- Ничья, если итоги отличаются меньше чем на 0.05 балла (это ~7% раундов). Правило «меньше 3%» на шкале 3–10 давало бы ничью в каждом четвёртом раунде.
- Чип меты показывает задание, а не название метрики: «БОНУС РАУНДА · Брови вверх ×2».
- Ключевая линия на лице (акцентная) по-прежнему показывает, что сейчас в мете.

## Архитектура

```
index.html               разметка: видео, оверлей, панели, кнопки, экраны
css/app.css              токены (:root) и все стили
manifest.webmanifest     PWA, display: fullscreen
sw.js                    офлайн: оболочка (stale-while-revalidate) + тяжёлые ассеты (cache-first)
js/
  main.js                сборка модулей, цикл кадров, fullscreen, Wake Lock, гигиена киоска
  bus.js                 шина событий (список событий в комментарии)
  fsm.js                 универсальная машина состояний с таймерами, привязанными к состоянию
  settings.js            localStorage + скрытый лист настроек + долгое нажатие
  camera.js              getUserMedia, список камер, понятные ошибки
  tracker.js             MediaPipe: GPU→CPU fallback, мозаика тайлов, поиск лиц, адаптация под fps
  assign.js              слоты L/R: присутствие, стабильность, смена людей, гистерезис перестановки
  view.js                кадрирование отображения, маппинг координат камеры на экран
  face.js                индексы лэндмарков, поза из матрицы, фронтализация, геометрия
  metrics.js             шесть метрик 0..1, EMA, среднее за скан
  score.js               веса, мета, шум, итог по шкале 3–10, ничья
  render-lines.js        canvas: овалы, скобки, линии, скан-линия, красная полоса MOGGED
  render-ui.js           DOM: видимость по состояниям, карточки счёта, отсчёт, результат
  audio.js               WebAudio-синтез: тик, отсчёт, удар
  modes/duel.js          режим дуэли: idle → ready → meta → countdown → scan → reveal → result
scripts/
  fetch-assets.mjs       скачивание wasm, модели, шрифтов (Node 18+, без зависимостей)
  serve.mjs              локальный сервер с правильными MIME (wasm и др.)
start.bat                запуск на Windows
.github/workflows/pages.yml   деплой на GitHub Pages
```

Режим общается с остальными модулями только через события (`round:meta`, `round:countdown`, `round:scan`, `score:live`, `round:lock`, `round:result`, `series`, `hint`, `notice`). Новый режим (например, Face Off) пишется как ещё один файл в `js/modes/`: он слушает `frame` и `tick`, эмитит те же события, а UI, линии и звук переиспользуются без правок.

## Дизайн-токены

```css
--bg: #0A0A0B;   --text: #F5F5F7;   --text-2: #9A9AA1;
--hairline: rgba(255,255,255,.14);   --panel: rgba(10,10,11,.64);
--accent: #4D8DFF;     /* победитель: число, полоска, обводка, тег; ключевая линия */
--mog: #FF3B30;        /* проигравший: только полоса MOGGED */
--scrim: rgba(10,10,11,.32);   --dim: rgba(0,0,0,.4);

--fs-score: 13vh (800, −.045em)   --fs-count: 40vh (800)
--fs-hint: 5vh (700)              --fs-chip: 4vh (800)
--fs-button: 3.4vh (700)          --fs-label: 2vh (700, uppercase, .1em)
MOGGED: Inter 900, ≈ 0.6 толщины полосы, белым по красному
--edge: 4vh   --radius: 2.4vh   --btn-h: 10vh   --card-w: 46vh
--ease: cubic-bezier(.2,.8,.2,1)   180 / 280 / 420 мс
```

Цвета меняются одной строкой, canvas читает токены из CSS. Анимируются только `transform`/`translate`/`scale` и `opacity`. Нет blur, backdrop-filter, теней, градиентов и эмодзи. Полоса MOGGED прочерчивается слева направо за 240 мс.

## Метрики и очки

На экране только итог. Внутри считаются шесть метрик:

| Метрика | Что меряется (реально) |
|---|---|
| JAWLINE | угол челюсти «уровень уха → угол челюсти → подбородок» во фронтальной проекции + бонус за поднятый подбородок |
| CANTHAL TILT | наклон линии «внутренний → внешний уголок» относительно линии внутренних уголков |
| SYMMETRY | отклонение 40 зеркальных пар лэндмарков от общей оси / межзрачковое расстояние |
| BROW LIFT | blendshapes `browInnerUp`, `browOuterUp*` |
| STARE | время без моргания (`eyeBlink*`) + прямой взгляд (`eyeLook*`) |
| AURA | неподвижность головы + закрытый рот (`jawOpen`) + без улыбки (`mouthSmile*`) |

- Поворот головы компенсируется фронтализацией через facial transformation matrix, масштаб нормируется на межзрачковое расстояние. При повороте больше 32° врождённая геометрия «замораживается», а AURA получает штраф.
- Каждая метрика 0..1, затем возводится в квадрат и умножается на шум ±8% (фиксируется на раунд). Взвешенная сумма `raw` переводится в итог `3 + 7·√raw`. Типичное «пассивное» лицо получает ~6, лицо, которое играет мету, ~8.5.
- Врождённая геометрия даёт не больше 40% итога даже при мете. Мета случайна, не повторяется подряд и даёт ×1.5–×2.
- Итог считается по среднему за 4 с скана, поэтому одно моргание раунд не решает. Если разница меньше 0.05 балла, MOGGED получают оба.
- Во время скана то же значение без шума показывается вживую, чтобы игроки видели, как лицо двигает число.
- Метрику, которая решила раунд, видно только в `?debug` (`res.decisive`).

Калибровка диапазонов лежит в `CAL` в начале `js/metrics.js`. Откройте `?debug` и смотрите в консоли `mog.players.L.read` / `mog.players.L.q` на реальных людях.

## Приватность

После загрузки приложение не делает ни одного сетевого запроса (проверено с выключенным сервером). Кадры идут из `<video>` прямо в детектор и на экран: не записываются, не кодируются, никуда не отправляются. В `localStorage` лежат только настройки.

## Что проверено, а что нет

В headless Chromium с фейковой камерой (тестовый портрет MediaPipe) проверено:

- полный раунд от idle до result с крупными лицами и с лицами на 5% ширины кадра;
- движение лиц;
- уход лица посреди раунда: раунд прерывается, затем ready → idle;
- один игрок: подсказка «Нужен второй игрок»;
- экран без камеры;
- лист настроек и долгое нажатие;
- ничья;
- офлайн-загрузка после первого визита;
- юнит-проверки очков (веса, потолок 40%, шкала, частота ничьих);
- память: куча JS стабильна (~50 МБ) на длинном прогоне.

Оба делегата прогнаны: CPU (XNNPACK) и GPU, но GPU только программный (SwiftShader, в 20 раз медленнее настоящего). Захват лиц держится даже на 2 детекциях в секунду.

ESLint: 0 ошибок.

**Не проверено на настоящем железе:** скорость на Iris Xe (GPU-делегат), реальная камера панели, мультитач, звук. Это и есть чек-лист ниже.

## Чек-лист «проверить на панели»

1. **FPS.** Настройки → Оверлей FPS → Вкл. Ожидается `≥ 30 fps`, `det ≈ 30`, `GPU`, время детектора около `< 20 ms`. Если там `CPU`, у Edge проблема с драйвером (проверьте `edge://gpu`). Если fps ниже 24, приложение само снизит вход (видно по размеру и `skip`).
2. **Свет.** Лица должны быть освещены спереди. Окно за спинами игроков (контровой свет) делает лица тёмными, и детектор их теряет. Проверьте со включённым верхним светом.
3. **Расстояние.** Норма 1–2 м. С оверлеем FPS видны тайлы детектора: пунктир значит поиск, сплошная рамка значит трекинг. Лицо должно ловиться меньше чем за 1 с. На 2.5 м и дальше лицо становится слишком мелким даже для самого маленького кропа поиска: попросите подойти ближе. Если панель стоит так, что ближе не встать, добавьте в `searchCrops()` в `tracker.js` ряд кропов размером `vh * 0.2`. «Детектор, px на игрока» меняет только чёткость лэндмарков, а не дальность.
4. **Углы линий.** Откройте страницу с `?debug` и в консоли смотрите `mog.players.L.read`. Встаньте ровно анфас: `roll` ≈ 0, `ct` обычно от +1° до +7°, `jaw` 120–145°. Наклоните голову на ~10°: `roll` ≈ ±10°, а `ct` почти не должен меняться (компенсация наклона). Если `ct` у всех отрицательный, напишите мне, значит перепутан знак.
5. **Итог.** Пассивно стоящий игрок получает ~6, тот, кто играет мету (брови вверх, не моргает, не улыбается), ~8+. Если все сидят на 9–10 или на 4–5, подстройте `CAL` в `metrics.js`.
6. **Зеркало.** Поднятая правая рука должна быть справа на экране.
7. **Автокадр.** Двое встают рядом, кадр плавно приближает. Один уходит, кадр отъезжает. Во время раунда кадр почти неподвижен.
8. **Касания.** Тап по кнопкам срабатывает сразу, щипок не зумит, удержание левого верхнего угла 1.5 с открывает настройки.
9. **Звук.** Тик, отсчёт и удар слышны, но не громко.
10. **Офлайн.** Запустите один раз с сетью, отключите сеть, перезапустите приложение.
11. **Масштаб Windows** 100–200%: пропорции интерфейса не меняются.

## Лицензии

MediaPipe Tasks Vision и модель Face Landmarker распространяются под Apache 2.0. Шрифты Inter и JetBrains Mono под SIL OFL 1.1, тексты лицензий скачиваются вместе с файлами.
